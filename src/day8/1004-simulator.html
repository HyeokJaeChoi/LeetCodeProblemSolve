핵심 아이디어 — 슬라이딩 윈도우

이 문제의 핵심은 "0을 최대 k번 뒤집을 수 있다"는 것을 "윈도우 안에 0이 최대 k개까지 허용된다"로 바꿔 생각하는 것입니다.

두 포인터 left와 right로 배열 위를 움직이는 창문(윈도우)을 만들고, right는 항상 앞으로만 이동하면서 윈도우를 확장합니다. 윈도우 안의 0이 k개를 넘으면 left를 오른쪽으로 밀어 윈도우를 줄입니다. 이때 매 순간 윈도우 크기(right - left + 1)가 곧 "0을 k번 뒤집었을 때 연속 1의 길이"입니다.

변수 선언 int left = 0;  int curr = 0;  int ans = 0; ▼
세 개의 변수를 초기화합니다.

left: 슬라이딩 윈도우의 왼쪽 끝 인덱스. 오른쪽 루프 변수 right와 함께 현재 윈도우의 범위 [left, right]를 정의합니다.

curr: 현재 윈도우 안에 있는 0의 개수. "몇 개의 0을 뒤집었는가"를 추적합니다. curr ≤ k이면 유효한 윈도우입니다.

ans: 지금까지 발견한 유효한 윈도우의 최대 크기. 최종 답이 됩니다.
외부 루프 for (int right = 0; right < nums.length; right++) ▼
right 포인터가 배열을 왼쪽에서 오른쪽으로 한 칸씩 전진합니다.

right는 절대 뒤로 가지 않습니다. 매 반복마다 윈도우의 오른쪽 끝을 한 칸 확장합니다.

left는 이 루프 안에서 필요할 때만 앞으로 이동합니다. 두 포인터 모두 한 방향으로만 가기 때문에 전체 시간 복잡도가 O(n)이 됩니다.
💡 right가 n번 전진, left도 최대 n번 전진 → 총 이동 횟수 최대 2n → O(n)
윈도우 확장 if (nums[right] == 0) { curr++; } ▼
right가 가리키는 새 원소를 윈도우에 편입시킵니다.

새 원소가 0이면 "0을 하나 더 뒤집은 것"이므로 curr을 1 증가시킵니다.
새 원소가 1이면 뒤집을 필요가 없으므로 curr은 그대로입니다.

우리가 1을 세지 않고 0만 세는 이유: 윈도우가 "유효"한지 판단하는 기준이 0의 개수이기 때문입니다. 1은 항상 원하는 값이므로 제한 없이 포함할 수 있습니다.
윈도우 축소 (while) while (curr > k) { ... } ▼
윈도우 안의 0이 k개를 초과하면 — 즉, 허용된 횟수보다 더 많이 뒤집어야 하는 상태가 되면 — 윈도우가 무효입니다.

이때 left를 오른쪽으로 밀어 윈도우 왼쪽을 잘라냄으로써 윈도우를 줄입니다. curr ≤ k가 될 때까지 반복합니다.

왜 if가 아니라 while인가?
실제로는 right가 한 번에 한 칸만 이동하고, 그때 추가되는 0은 최대 1개이므로 curr은 최대 1만 초과합니다.
따라서 이 경우엔 if와 while이 동일하게 동작합니다.
그러나 일반적인 슬라이딩 윈도우 패턴으로서 while을 쓰는 것이 정석입니다. "조건이 해소될 때까지 계속 줄인다"는 의도를 명확하게 표현합니다.
윈도우 축소 (내부) if (nums[left] == 0) { curr--; }  left++; ▼
left가 가리키는 원소를 윈도우 밖으로 밀어냅니다.

밀려나는 원소가 0이면: 그 0은 더 이상 윈도우 안에 없으므로 curr--로 0의 카운트를 줄입니다.
밀려나는 원소가 1이면: curr에 영향을 주지 않습니다. 그냥 left++만 합니다.

이 두 동작 이후 left가 한 칸 앞으로 이동하여 윈도우가 왼쪽에서 하나 축소됩니다.
🔑 핵심: curr은 항상 현재 윈도우 [left, right] 안의 0의 개수를 정확하게 반영합니다. left가 이동할 때마다 동기화합니다.
최댓값 갱신 ans = Math.max(ans, right - left + 1); ▼
while 루프가 끝나면 현재 윈도우 [left, right]는 반드시 유효한 상태(curr ≤ k)입니다.

이 유효한 윈도우의 크기 right - left + 1과 지금까지의 최댓값 ans를 비교해 더 큰 값을 저장합니다.

왜 +1인가? 인덱스 기반이므로 길이 = 끝 인덱스 - 시작 인덱스 + 1. (예: [2, 5] → 길이 4 = 5-2+1)

이 한 줄이 루프의 마지막마다 실행되기 때문에, 모든 가능한 유효 윈도우의 최댓값이 자동으로 기록됩니다.
반환 return ans; ▼
루프가 끝나면 ans에는 "최대 k번 0을 뒤집었을 때 만들 수 있는 연속 1의 최대 길이"가 담겨 있습니다.

right가 배열을 끝까지 한 번 훑는 동안 발생했던 모든 유효 윈도우 중 가장 큰 크기가 곧 정답입니다.
✅ 전체 시간 복잡도: O(n) — left, right 각각 최대 n번 이동
✅ 전체 공간 복잡도: O(1) — 추가 배열 없이 변수 3개만 사용
